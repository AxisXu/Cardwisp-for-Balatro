# 商店决策流程（第一版）

本流程只给玩家建议，不执行购买、出售或重掷。现在接入的是本机 Codex CLI 桥接；直连兼容模型服务仍使用原先的局面提示。局面来自游戏当前可见数据，未开卡包内容与未来商店保持未知。

1. **锁定局面**：玩家发送问题时，桥接程序在同一把会话锁内读取本局最新快照、商店版本和模型设置。旧版快照不会覆盖新版快照。
2. **识别问题**：模型结合玩家原话与当前阶段，判断是商品选择、重掷、单卡效果还是其他问题；玩家未问商店选择时，不强制回答整家商店。
3. **核对依据**：桥接程序对每件可见商品读取实际售价，计算扣除这笔直接费用后的基础余额、余额对应的利息档位、可负担性与槽位状态，并读取当前重掷价。动态加成沿用游戏可见数值。无法确认的字段保持 `null`，不当作零；未开卡包的内容标为未知。
4. **比较选项**：模型根据玩家的问题比较购买、暂缓、出售腾槽或重掷等相关方案。满小丑槽时，程序列出每张普通可出售小丑与新商品的“先卖后买”方案，核对出售所得、直接交易后余额、可负担性和余额对应的利息。永恒小丑与负片小丑不作为简单腾槽方案；缺失售价时不把它当零。模型再比较保留旧牌与替换的当前贡献、配合和未来成长。确定性数字以核对结果为准；卡牌强度和构筑价值仍是模型判断，尚无按需查牌、算分或搜索工具。
5. **给出建议**：回复先给结论和关键理由。缺少足以改变结论的数据时说明条件。如果等待模型期间可见局面变化，桥接程序丢弃旧回复，并提示玩家重新提问。

自动验证覆盖：商店重掷后的商品列表、售价与利息计算、免费重掷、满槽、缺失数据，以及提问后商品或金币变化。真实游戏中的回答质量和响应时间还需单独验收；自动测试不证明模型的策略判断一定正确。

“先卖后买”的账目只包括可见售价与商品价，不预测出售或购买触发的其他卡牌效果。牌灵仍不会执行出售。构筑目标目前主要由模型结合当下局面推断，尚未持久记录为可修订的整局计划。

## 规则来源与边界

2026-10-09 对照本机 Steam 版 `Balatro.app/Contents/Resources/Balatro.love` 内的游戏代码核对，未把游戏代码复制进插件：

| 核对事实 | 游戏代码位置 | 牌灵的计算边界 |
| --- | --- | --- |
| 商品价格与扣款 | `functions/button_callbacks.lua:2464-2468`；插件从卡牌的 `cost` 字段读取价格 | 只计算当前金币减去直接费用，不预测购买触发的小丑效果 |
| 购买与重掷是否付得起 | `functions/button_callbacks.lua:55-62, 96-118, 2076-2086` | 使用当前金币、`bankrupt_at` 和显示价格；普通免费商品、免费卡包与免费重掷允许在余额低于债务线时使用，免费优惠券仍按其按钮规则判断 |
| 槽位 | `functions/button_callbacks.lua:2392-2401` | 当前小丑和道具数量与槽位比较；负片版本额外允许占一个位置。满槽只表示要先腾槽，不替玩家出售 |
| 出售小丑 | `card.lua:1590-1649` | 游戏出售时使用卡牌当前的 `sell_cost`，永恒小丑不可出售；牌灵只列出普通非永恒牌的直接出售所得，不模拟出售触发效果或操作期间的临时锁定 |
| 当前重掷价格 | `functions/common_events.lua:2263-2269`；`functions/button_callbacks.lua:2855-2871` | 以游戏当前 `reroll_cost` 为准。免费重掷在游戏内已把该价格设为零；不预测下次价格或刷新的商品 |
| 利息 | `functions/state_events.lua:1191-1202` | 金币至少 $5 且允许利息时，按 `interest_amount × min(floor(金币/5), interest_cap/5)` 计算。展示的是“若余额保持不变，到下一次结算可处于的利息档位”，不是购买当下入账，也不含接下来打牌、购买或卡牌效果造成的金币变化 |

本机游戏和 Steamodded 等模组日后更新时，需要重新核对会修改这些规则的补丁。当前计算是游戏原生规则下的只读基础估算，不是对所有模组组合的最终收益模拟。
