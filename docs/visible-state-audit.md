# 牌灵可见局面审计

牌灵只读取当前牌局中玩家可见、会影响建议的信息。游戏内快照约每秒同步到本机桥接服务；只有玩家发送问题时才交给模型。下表按 Balatro 1.0.1o 的本机游戏代码核对。

商店商品、金币或重掷价变化，以及开包候选牌、出牌手牌或盲注选择变化时会立即发布新快照；每份快照带递增版本，迟到的旧版不会覆盖新版。本机服务记录商店状态版本和上一份商品清单。模型提问时，最新局面放在聊天历史之后，并明确以它为准。`/v1/session` 可用于只读核对模型实际能看到的当前商品和版本；回答也记录它所用的商店状态版本，便于区分“游戏没同步”和“模型读到了却说错”。

| 界面来源 | 传给模型的内容 | 边界 |
| --- | --- | --- |
| 商店与金币栏 | 当前金币、实际重掷价格、免费重掷次数、商品价格与卡牌修饰、利息倍率/封顶金额/按当前金币计算的利息、手牌和弃牌的结算收入规则、租赁小丑的回合费用 | 使用游戏当前价格，不预测重掷后商品 |
| 小丑与道具区 | 顺序、名称、卖价、版本、蜡封、永恒/租赁/易腐及剩余回合、可直接读取的效果文字与公开数值；常见养成小丑单列当前加成和每次触发变化量 | 背面卡不读取身份；尚未映射的动态文案数值记为 `?` |
| 出牌区 | 明牌的点数/花色/强化/蜡封/版本/选中状态、手牌上限、剩余出牌与弃牌、当前牌型计分显示 | 背面手牌不读取点数和花色 |
| 查看牌组与比赛信息 | 整副牌的公开清单、尚未打出的牌、牌堆和弃牌数量、可见牌型等级/基础筹码与倍率/使用次数、牌组与难度、已购优惠券及标签、当前可见的盲注列表；这些信息在商店、开包、出牌和选盲注阶段均可读 | 不读取抽牌顺序；不包含尚未解锁显示的牌型或隐藏盲注 |
| 盲注与开包 | 当前盲注目标/奖励/效果；可选盲注目标/奖励/效果/跳过标签；Boss 重掷价格与可用性；已打开卡包的选项和剩余选择次数 | 未打开的卡包内容、隐藏盲注和背面选项保持未知 |

效果文案来自游戏当前语言的本地化表，不复制进发布包。对照原版游戏的提示变量规则，牌灵会填入已验证的成长数值，例如「备用裤子」的每次增长与当前倍率、「跑步选手」的每次增长与当前筹码、「杂耍师」的手牌上限与「偶数史蒂文」的倍率。`current_bonus.value` 是卡牌当前加成，`per_trigger` 是每次触发的变化量；两者不可混淆。扑克牌永久筹码加成也单独传递。

Balatro 的部分效果在悬停提示中实时计算；牌灵的纯读取快照不调用会创建界面对象或修改卡牌状态的游戏提示函数，因此尚未映射的动态数值无法保证精确还原。出现 `description_unresolved` 或 `effect_unresolved` 时，模型只能把剩余的 `?` 当未知量，不应猜测。模组新增的小丑牌也默认遵守这一边界。

## 重掷后的局面误读案例

2026-10-09 的一次实机反馈中，上一家店是「无面小丑／奇数托德」，重掷后是「第六感／精明小丑／两个标准包」。本机服务的局面快照已经包含后者，模型也复述了后者，却称它们是“旧商品”并要求玩家再发截图。这次故障属于**模型对最新局面与聊天历史的优先级判断错误**，不能归类为游戏数据未读取。

回归测试先发布旧商店，再发布新商店，随后模拟迟到的旧快照，并检查提问时的上下文只以新商店为当前清单。后续排查同类问题时，先依次核对游戏画面、本机 `/v1/session` 的当前快照及版本、该条回答记录的版本，再判断是字段缺失、传输过期，还是模型解释错误。这样可把真实故障留成可复现的产品测试样本。
